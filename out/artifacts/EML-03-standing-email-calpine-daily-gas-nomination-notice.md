## Purpose

Give the gas logistics desk one reusable email for the recurring "Calpine Daily Gas Nomination" notice, so the same message can be assembled from a fixed template and, later, generated by a scheduled job instead of retyped.

## Scope

Covers the nomination notice sent from Calpine to the Enron gas logistics scheduler under the subject line "Calpine Daily Gas Nomination". Covers the subject line, addressing, send window and filing of that message. Does not cover the downstream nomination entry into the pipeline system, imbalance settlement, or any other Calpine correspondence.

## Current practice

The notice arrives as an email carrying the subject line "Calpine Daily Gas Nomination" [cit_61f81d3ab9f5]. The subject line is byte-identical on each recurrence and carries no flow date, cycle marker or revision number [cit_b843b41c8654]. It is sent from a single external address, `rickya@calpine.com`, on the Calpine side [cit_ba466aea576b]. The same address remains the sender across the series [cit_4e2ac2d3f0d4]. The message is filed into the `logistics` folder of the Enron scheduler's mailbox [cit_70d1c123124d]. Sends land in the early morning hours, ahead of the scheduling day: 00:20 Pacific on one instance [cit_4cccefa9b11b] and 00:24 Pacific on the next [cit_afa39320fe4b]. The series recurs across months rather than as a one-off exchange [cit_8eaeeb47890d].

## Template

Subject line kept stable for threading and filing, with the flow date added as a field so each instance is identifiable.

```
To:       {{scheduler_email}}
Cc:       {{standing_distribution_list}}
From:     {{nominating_party_email}}
Subject:  Calpine Daily Gas Nomination - flow date {{flow_date}} - cycle {{nomination_cycle}}

Nomination for flow date {{flow_date}}, cycle {{nomination_cycle}}.
Revision: {{revision_number}}  (1 = original)

Pipeline: {{pipeline}}
Contract: {{contract_number}}

Receipt points
  {{receipt_meter_number}}  {{receipt_meter_name}}  {{receipt_volume}}

Delivery points
  {{delivery_meter_number}}  {{delivery_meter_name}}  {{delivery_volume}}

Total nominated: {{total_volume}}

Changes from prior submission for this flow date:
  {{change_notes}}

Please confirm receipt to {{nominating_party_email}} by {{confirmation_deadline}}
<to be confirmed>.

Questions on volumes or points: {{nominating_party_contact}}, {{nominating_party_phone}}.
```

Field notes for whoever operates the template:

- `{{flow_date}}` and `{{nomination_cycle}}` are the two fields that make an instance findable later; do not leave them blank.
- `{{revision_number}}` distinguishes a replacement from a first submission. The archive does not show how revisions were marked, so treat this as new practice.
- `{{confirmation_deadline}}` is marked `<to be confirmed>` because no cutoff is evidenced.

## Recommended change

1. Adopt the subject line above, keeping the leading string "Calpine Daily Gas Nomination" so existing mail rules and folder filing continue to work, and appending flow date and cycle.
2. Ask the nominating party to populate the template rather than free-text the body. One agreed field order means the receiving scheduler reads the same positions every time.
3. Replace hand-typed volumes with a scheduled job that pulls receipt and delivery volumes from the nomination system of record, renders this template, and sends it to the standing distribution list on the agreed cadence. Route the job's output through the same address so filing rules are unaffected.
4. Have the job send an explicit "no change from prior nomination" message when volumes are unchanged, so a silent gap is never ambiguous.
5. Log each generated instance with flow date, cycle and revision number in a single register, so a missed or duplicated notice is visible without searching mailboxes.
6. Agree a confirmation path with the counterparty — reply to the generated mail, or acknowledgement in the scheduling system — and write the deadline into `{{confirmation_deadline}}` once fixed.
